# CHAT-UX-03 — 오류·중단 안내 검증

사용자는 지연 안내를 제외하고 오류·중단 안내를 명확히 하도록 요청했다.
언어 설정과 선택 언어의 `/status`는 [준비안](../implementation/CHAT_LANGUAGE_PREPARATION_2026-09-13.md)에
남기고, 이번 소스 변경은 현재 한국어 오류·중단 안내에 한정한다.

## 변경 결과

- 시간 초과, 호스트 작업 실패, 실행·작업 결과 불확실에 서로 다른 안내를 제공한다.
  시간 초과가 함께 발생해도 실행 불확실을 우선하고, 내부 panic 값은 표시하지 않는다.
- Telegram의 활성 `/cancel`·`/reset`은 해당 명령의 receipt를 따로 보관하고,
  실행 종료와 프로세스 정리를 확인한 뒤 결과를 한 번 답한다. 반복 요청에는 이미
  중단 요청 중임을 안내한다. 지연 타이머나 별도 진행 메시지는 추가하지 않는다.
- 답변 완료와 중단 요청이 겹치면 실제 완료·실패·중단·불확실 결과를 구분한다.
  이미 시작한 업무의 취소·원상복구를 약속하지 않는다.
- `/reset`의 실행 정리가 실패하면 새 대화 시작을 성공으로 안내하지 않는다.
- 로컬의 인자 없는 `/cancel`은 현재 답변을 뜻하며, 진행 중인 답변이 없으면 그대로
  알린다. `/cancel JOB_ID`는 기존 작업 제어 경로를 유지한다.
- 로컬에서도 불확실한 실행을 일반 취소 완료로 표시하지 않는다.

## 실행한 확인

| 확인 | 결과 |
|---|---|
| `go test ./internal/reception ./internal/telegramchat ./internal/cli` | 통과. 세 패키지에 테스트 파일이 없어 컴파일 확인이다. |
| 같은 세 패키지의 `go vet` | 통과 |
| 별도 경로의 `go build ./cmd/chunsu` | 성공. 운영 중인 checkout 바이너리는 교체하지 않았다. |
| AI 없는 별도 데이터 홈의 실제 CLI | `/cancel` → 진행 중 답변 없음, `/reset` → 새 대화, AI 실패 후 `/errors` → 설정 누락 안내, `/status` → 기존 구조화 상태, 다시 `/cancel` → 정상 안내, 종료 코드 0 |
| 독립 Terra 검토 | 실행기 내부 취소와 사용자 취소의 구분, 오류 안내 뒤 명시적 종료 유지 두 항목을 보정하고 재확인 |

검토 보정 뒤 위 세 패키지의 컴파일·정적 검사와 별도 바이너리 빌드를 다시 통과했다.
CLI 실행 확인은 기본 명령과 AI 미설정 경로에 한정하며, 보정한 경합·불확실 종료
분기는 소스 검토로 확인했다.

별도 검증 홈은 `/Users/yangmyeongsu/.chunsu-validation/chat-errors-ixyZBI`다.
CLI 출력은 그 안의 private `command-walkthrough.txt`에 보존했고, 운영 데이터나
비밀값을 복사하지 않았다. 새 테스트 소스는 만들지 않았다.

## 확인하지 않은 범위

실제 Telegram 메시지 전송, 활성 생성 중 취소·완료 경합의 실행 주입, 네트워크 전송
불확실, orphaned 실행·복구 실패 주입은 이번에 실행하지 않았다. 독립적인 Terra
소스 검토와 컴파일 성공이 해당 전달 시나리오의 실행 검증을 뜻하지 않는다.

운영 Telegram 서비스는 재시작하지 않았고 실행 중인 프로세스에는 아직 이 소스가
적용되지 않았다. 언어 설정·다국어 문구·JSON 상태 표시 변경·Telegram 메뉴 등록도
이번 결과가 아니다.
