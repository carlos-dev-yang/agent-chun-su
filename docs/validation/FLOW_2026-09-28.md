## Local commands for a disposable walkthrough

Use a private non-temporary test directory for actual Codex calls. All commands must carry `--home`; `flow run` is a local foreground executor and must not be used while the controller owns that home.

```sh
TEST_ROOT="$(mktemp -d "$HOME/.codex/chunsu-flow.XXXXXX")"
TEST_HOME="$TEST_ROOT/home"
CHUNSU_BIN="$TEST_ROOT/chunsu"
CODEX_BIN="$(command -v codex)"
go build -o "$CHUNSU_BIN" ./cmd/chunsu
"$CHUNSU_BIN" --home "$TEST_HOME" setup
"$CHUNSU_BIN" --home "$TEST_HOME" config route task --driver codex --path "$CODEX_BIN" --model gpt-6-sol --effort xhigh --environment native-restricted
"$CHUNSU_BIN" --home "$TEST_HOME" config policy apply
"$CHUNSU_BIN" --home "$TEST_HOME" config policy show
"$CHUNSU_BIN" --home "$TEST_HOME" flow submit mail-review examples/mail/synthetic-day.json --objective 'Review the synthetic mail snapshot.' --checkpoint
"$CHUNSU_BIN" --home "$TEST_HOME" flow run JOB_ID
"$CHUNSU_BIN" --home "$TEST_HOME" flow inspect JOB_ID
"$CHUNSU_BIN" --home "$TEST_HOME" flow artifact JOB_ID COLLECT_ARTIFACT_ID
"$CHUNSU_BIN" --home "$TEST_HOME" flow approve REFINE_STEP_ID
"$CHUNSU_BIN" --home "$TEST_HOME" flow run JOB_ID
"$CHUNSU_BIN" --home "$TEST_HOME" flow artifact JOB_ID REFINE_ARTIFACT_ID
"$CHUNSU_BIN" --home "$TEST_HOME" flow result EVENT_ID
```

`flow pause JOB_ID`, `flow resume JOB_ID`, and `flow retry STEP_ID FAILED_ATTEMPT_ID` are explicit controls. `flow result preview EVENT_ID` shows only what the active local conversation may receive. `flow result recover EVENT_ID` classifies an abandoned `sending` receipt as `unconfirmed` only after acquiring its per-conversation sender lease. Inspect it, then use `flow result resolve EVENT_ID sent` if the user received it, or `flow result resolve EVENT_ID retry` if the owner chooses a new send. Unknown sends are never replayed automatically. The same controls are available to an active chat with `/job` commands; `/job select PRIOR_CONVERSATION_ID JOB_ID` explicitly imports one link after reset.

Saved Jira and code fixtures are `examples/jira/report-input.json` and `examples/code-review/synthetic-change.json`. Jira currently demonstrates admission, host collection and safe provenance rejection; code now has a complete synthetic report path. Public web uses `flow web 'QUERY'`, requires `/web enable` and an owner-configured Brave key, and remains bounded to public HTTPS search/open. The test home must be configured explicitly; do not simulate a Brave response as live evidence.

## Existing-home activation procedure (not performed)

The owner must make an operational decision and schedule this separately. The current self-updater intentionally refuses schema-changing updates; normal `/update` is not a schema-5 migration path.

1. Stop the controller/worker/receiver that owns the existing data home and verify the writer is idle. Record the installed binary and its schema version.
2. With the old binary, run `OLD_BIN --home "$DATA_HOME" backup "$BACKUP_DIR"` and `OLD_BIN --home "$DATA_HOME" verify-backup "$BACKUP_DIR"`; preserve a rollback copy and the prior binary. Use a new private backup directory.
3. Stage the reviewed new binary. Run `NEW_BIN --home "$DATA_HOME" setup` explicitly while services are stopped; this is the schema migration point. Inspect `NEW_BIN --home "$DATA_HOME" doctor`, `jobs`, and `config policy show` before restarting.
4. Set the executable and environment with `NEW_BIN --home "$DATA_HOME" config route task --driver codex --path "$CODEX_BIN" --model gpt-6-sol --effort xhigh --environment native-restricted`, then run `config policy apply`. This opts in to Sol medium chat, Luna xhigh collection/refinement, and Sol xhigh synthesis/task/review; it revokes prior disclosure grants. Confirm exact role routes with `config policy show`.
5. Grant each private source and role deliberately, for example `NEW_BIN --home "$DATA_HOME" config grant refinement mail --allow`, `NEW_BIN --home "$DATA_HOME" config grant synthesis mail --allow`, and `NEW_BIN --home "$DATA_HOME" config grant reception mail --allow` if the chat may read the report. Code uses `code` similarly. Jira refinement/synthesis additionally require `NEW_BIN --home "$DATA_HOME" config grant refinement jira --allow --policy-digest POLICY_SHA256 --proof COMPLETED_SYNTHETIC_JIRA_JOB_ID` and the analogous synthesis command. `config grant` reopens and verifies the exact role's synthetic proof. Reception Jira has no private handoff proof route, so Jira detail stays on the owner CLI. `NEW_BIN --home "$DATA_HOME" config grant ROLE SOURCE` without `--allow` revokes that one grant. Do not copy old task grants to new roles.
6. Recheck `doctor` and start the owner-approved services. Run one bounded synthetic job before any live source use. Roll back using the preserved prior binary and backup if migration or validation fails; a schema-5 database must not be reopened with the old binary.

The macOS 0.158 tool-free structured route evidence does not validate Linux, another CLI version, native-MCP task execution, a live Jira/mail/code account, or Telegram delivery. Those require separate host-specific checks and owner-controlled source grants. No production data home or service was changed during this development work.
