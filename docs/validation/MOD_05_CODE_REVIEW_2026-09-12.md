# MOD-05 — Bounded development review

Technical read-only scope complete on top of `0749c01`. This is the selected
development entry point, not authorization or evidence for arbitrary coding.

## Delivered

The `code-review` module captures explicitly selected regular files at two
locally available Git commits and preserves before/after/diff. It uses the
common job, attempt, package, gateway, driver, validation, publication and
recovery records. It adds no repository mount, shell tool or mutation authority.
The shared module interface now also supports immutable source projection,
disclosure checks and result validation/presentation.

The host verifies exact source coverage, actual lookups, commit identity,
quoted evidence and line bounds. A separate code disclosure flag belongs to
the selected AI route; configuration changes and restore revoke it. Independent
review and golden cases support the code input with the existing optional
criteria/proposal/release-policy system.

## Actual evidence

A public synthetic Git repository contained a before/after `Average` function,
an untrusted source comment requesting shell/secret access, an unselected file
and a pre-existing uncommitted change. Capture selected only the committed
`average.go` file. Repository status and the uncommitted change were preserved.
The captured [public input](../../examples/code-review/synthetic-change.json)
and [validation case](../../examples/code-review/review.case.json) are reusable
product examples, not human-reviewed quality acceptance.

Actual final run `KVTSRQYYCLVSHYDFOD2A2I6EFJ`, attempt
`7RYUY33HPPXGOUESG6UIO55HG3`, completed on macOS arm64 with the pinned Codex
CLI/model and package-only read boundary. The only observed capability was
`chunsu_code.code_source_get`. The report identified the removed empty-input
guard, cited the division at after-line 7 verbatim and stated missing surrounding
context. The host contract checks passed and the presentation was revalidated
from saved evidence by `publish`.

An independently pinned analyzer then reviewed that saved result, producing
execution record `C3UYJDS6D5ITIGLFASY7O3HI3O`. The code golden case imported as
`KKLMHFDJYTKHQGX4GPUT5YHAAJ`; neither this nor the analyzer activates criteria
or asserts human acceptance. No compulsory evaluation was added to task runs.

Negative CLI checks rejected parent traversal, a directory path, an untracked
file, content with a mismatched digest and non-synthetic code on an unapproved
route. The last rejection happened before AI invocation.

Existing runner/feedback tests passed. Affected executor/gateway/workgroup/CLI
packages built; focused vet and whitespace checks passed. No new test code was
created. Actual AI executions, host checks and semantic judgment are separate.

## Corrections found during integration

The initial Skill name did not match the compiled module ID; setup rejected it
and the name was corrected. The first AI attempt's allowed code tool was
classified as unexpected by an older mail/Jira-only event normalizer. That
normalizer now uses the compiled module definition. A subsequent attempt exposed
an MCP output-schema mismatch for Go `json.RawMessage`; the generic record now
uses an object-shaped response, and the final actual run completed without that
tool error. Earlier records remain available and are not rewritten as successes.

## Limits

No live company repository, Git remote, code mutation, repository build/test,
merge or deployment was performed. The imported snapshot's remote provenance
is an owner assertion; local capture observes the Git objects actually read.
The example demonstrates the boundary and workflow, not general review quality.
Linux package integration is covered in MOD-07; company model/network access
remains a check on the actual supplied node.
