# CHAT-TONE-01 — Separate style instructions

The user can open `/말투` or `/말투 옵션`, choose a numbered preset or enter
custom text, inspect the setting, cancel selection or reset to the default.
The shared local/Telegram menu is mechanical and runs before AI admission.
Preset instructions are embedded Markdown files; the active instruction is
stored only in the data home's private `instructions/chat-tone.md`.

Every reception generation reloads this file and injects it as a distinct
host-labeled style section. The base Skill, capability/schema contracts,
conversation history and task/review agent instructions stay separate. Missing
or empty Markdown means default style. The selected text is bounded by the named
style limit and configured limits, and combined prompts retain their existing limit.

code changes, excluding concurrently edited operations-monitor code. This was a
build directory, not a Git worktree. Runtime checks used a separate private data
home and did not set a tone in the actual owner's data home.

  `/reset` and a new CLI process both retained the setting. Before enabling an
  executor there were no executor records, confirming these menu operations

- After copying only the existing reception driver configuration into the
  isolated home, a real Codex reply followed the custom prefix/style instruction.
  A fresh process performed runtime_status and its final answer followed the
  same instruction, with internal action messages still suppressed.

- The custom marker appeared in the active Markdown, but in none of the 16
  generated chat artifacts inspected; style/menu text was not copied to traces.
- Independent Terra review found no concrete introduced defects in scoped

No new test source was added. Oversized/invalid-UTF-8 input, concurrent writers,
and actual Telegram menu selection were not exercised at runtime. Code review
