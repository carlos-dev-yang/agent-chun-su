## 기존 수집기의 실제 실행

독립 Terra 검토자가 원문에서 기대값을 만든 후 기존 `jira inspect`,
`jira collect`, `jira show`, snapshot 조회와 `jira source` 경로를 사용했다.
실행 파일의 애플리케이션 코드는 `73e67d0`까지의 검증된 빌드와 같다.

| 그룹 | acquisition | 결과 |
|---|---|---|
| 기한 임박 | `I7GQWIXKAF7IPXG2L5SMNRUHAP` | 3건, collected, complete |
| 기한 경과 | `CSHN55D4F5UBWY4ADYN4AL7PR6` | 7건, collected, complete |
| 기한 없는 TODO | `EDCMYDB5NMPWUBBLKKZLHW35YN` | 16건, collected, complete |

세 acquisition 모두 `saved-responses-v1`, `synthetic=false`, 한 페이지,
`end_of_source`로 기록됐다. 조회 경로가 다시 검증한 원문은 각 실제 HTTP
응답과 바이트 단위로 같았다. 실제 수집 시각도 같은 순간으로 보존됐다.
이 `complete`는 기존 v1 수집 계약의 결과이며 Jira 보고서에 필요한 모든
정보가 정규화됐다는 판정은 아니다.

검증 스크립트는 UTC의 `Z`와 `+00:00` 표기를 문자열로 비교해 한 번
중단됐다. 수집 자체는 성공했으며, 같은 acquisition을 사용해 시각을 파싱한
뒤 비교했다. 이 과정에서 첫 그룹을 다시 수집하지 않았다.

## 기대값 고정 중 발견한 문제

최초 기대값 SHA-256은
`745e58fb16cd49c5a3c0f16a2527dd5823df4d83c82076390bbc4ed6b3616e00`이다.
호스트는 이 해시를 첫 수집 전에 시작 기록에 고정했다. 이후 검토자가
완료를 알린 같은 파일에 supporting metadata를 추가해, 후속 검증이
해시 불일치로 중단됐다.

최초 파일을 40,433바이트로 정확히 복원했으며 시작 기록의 해시와 일치했다.
두 버전을 별도 파일로 보존했고, 차이는 `supporting_capture_metadata`
하나이며 이슈 기대값이 같다는 점도 대조했다. 이후 검증은 해시가 이름에
포함된 최초 사본을 사용했다. 갱신본 SHA-256은
`093557b7fea1b72aa748a66a7e0f8cb649672da9cd23b8d5546b3fa7bb8ad94f`다.

두 중단은 검증 자료를 다루는 과정의 문제이며 collector 실패나 Jira AI
보고서 실패로 세지 않는다. [골든셋 규약](../skills/golden-evaluation.md)에
수동 기대값도 완료 통지 후 덮어쓰지 않고 실행 전 불변 사본을 고정하도록
명시했다. 기존 평가 기록이나 원문은 변경하지 않았다.

## 독립 대조와 평가 정정

독립 대조에서 26/26 key·raw issue ID가 반영됐고 중복·누락은 없었다.
프로젝트, 담당자, 상태, 기한, 제목, 설명 텍스트와 출처의 hash/pointer/시각이
대응했다. 최초 평가의 SHA-256은
`0d192216816df6c1755ed8af2f5d6c0f50cd00a8450fa6321e6402e4577272e9`다.

최초 평가는 본문 8건을 원문 미제공으로 판단해 `empty` 변환을 실패로
표시했다. 실제로는 26건 모두 `description` 필드가 있었고 8건은 명시적
`null`, 18건은 내용이 있는 문자열이었다. 별도 Terra 검토자가 원문과 기존
`presence`/`normalizedText` 규약을 대조해 수집기 결함이 아닌 기대값의

`not_configured`, report execution은 `deferred`다. Jira 연결 설정·수집 정책·
보고서 계약에 대해 앞서 요청한 사용자 확인은 답변 전이며, 이 점검을 새
계약의 확정이나 일정 활성화로 취급하지 않는다.

## 검증과 남은 범위

실제 GET 6건, 입력 검사 3건, 수집 3건과 각 state/snapshot/source 조회를
실행했다. 보존된 입력·snapshot·원문 참조 9개의 해시·바이트 수·0600 권한을
확인했고 독립 평가와 반대 근거 재검토를 수행했다. 변경은 문서뿐이므로
새 테스트 코드, 애플리케이션 재빌드, 전체 프로젝트 검사는 수행하지 않았다.

기존 메일 실행의 동일 원인 누적은 원문 조회 생략 2회, 근거 없는 미완료
확정 1회로 유지한다. 이번 수동 검증의 시각 표기 비교, 기대값 덮어쓰기,
`null` 오분류는 서로 다른 원인으로 각 1회이며 모델 실행 실패와 별도 기록했다.
어느 한 원인도 이번에 3회에 도달하지 않았다.

활성 mail workgroup digest는 기존 값과 같고 실메일 실행 승인은 비활성이다.
실계정 메일 자동 수집, Jira 공통 실행/평가, 장기 일별 실행은 여전히 남아
있다. 전체 목표 완료를 선언하지 않는다.
