# Core Contract v1

Date: 2026-09-06. Scope: the previously planned single-host Go + SQLite implementation. These names are local contracts, not a published remote API.

## State and ownership

A job is a durable user request. Each execution has a distinct attempt. The controller owns both. A job records its workgroup, input reference, status, current attempt, timestamps, retry eligibility, and a non-secret diagnostic. Attempts preserve status, ordinal, start/end, executor identity, and result reference. Events and artifacts link to their job and attempt.

The initial states are queued, running, retry_wait, waiting_input, waiting_auth, completed, partial, failed, and cancelled. Attempt states also include interrupted. A result may update its job only while its attempt is the current attempt and the expected running state still holds. Cancellation, timeout, retry, and a candidate experiment are different operations.

Controller mutations hold a per-data-root OS lock. Network/model work does not hold a SQLite transaction. Database writes use short transactions and a single connection/writer. Files are finalized before their DB references are published; incomplete files and orphaned artifacts are recoverable rather than reported as success.

## Files and records

Configuration is versioned JSON without secrets. Runtime paths are private to the user. Job and attempt IDs are generated by the host and validated before joining a filesystem path. The controller creates package and artifact paths; executor-supplied paths never select host files.

Artifacts have an ID, job/attempt link, kind, relative path, byte count, and SHA-256. Collected artifacts are never overwritten. File readers constrain paths to their data root and reject symlinks. A finalized report is locally available, not evidence that a human read it.

SQLite stores jobs, attempts, events, artifact references, and later evaluation/proposal/schedule relationships. The initial schema is applied only to an empty compatible DB. Each subsequent migration has an explicit version. The DB engine is embedded; a PATH SQLite executable is irrelevant.

## Configuration

Defaults are named operational limits with validation and user overrides: lock wait, executor timeout, retry count, artifact/source sizes, and retrieval limits. Provider endpoints and model/executor paths are configuration, not scattered literals. Setup preserves existing files and only creates missing defaults. Config errors do not silently reset user data.

Saved-input operation does not require Gmail or a running service. Diagnostic output exposes availability and version information, not credentials or private content. A secret reference identifies host storage without containing the secret.

## Completion and evidence

The host checks result shape, declared source references, target-source dispositions, and known acquisition failures. It applies complete/partial/wait policy independently from semantic evaluation. Missing or failed acquisition cannot be reported as a successfully empty mailbox. A malformed result remains available as failed evidence.

Evaluation judgments and optimization findings are separate records. Proposals identify candidate assets and evidence; adoption is an explicit human action. Adoption affects subsequent packages and preserves old runs and decisions.
