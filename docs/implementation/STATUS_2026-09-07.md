## 오늘 실행한 확인

현재 체크아웃을 대상으로 다음을 실행했다. 합성 수집은 별도 임시 애플리케이션
홈에서 실행했으며 기존 사용자 데이터·계정·활성 지침을 사용하지 않았다.
임시 홈은 저장 응답 수집에만 사용했고 AI executor를 실행하지 않았다.

| 확인 | 결과 |
|---|---|
| `CGO_ENABLED=0 go build`로 CLI 빌드 | 통과 |
| `go vet ./internal/jira ./internal/cli ./internal/store` | 통과 |
| `jira status` | 저장 reader ready, 실제 reader not_configured, 보고서 deferred |
| 입력 없는 `jira collect` | 종료 코드 1, not_configured, 새 애플리케이션 홈 생성 없음 |
| Cloud 합성 입력 inspect·collect | 입력 유효, 첫 페이지 3건, page_budget_reached |
| 같은 ID로 resume | 2페이지·8개 행·고유 이슈 3건. 수집은 종료되고 알려진 누락 때문에 스냅샷은 partial 유지 |
| alternate mapping 재정규화 | 새 ID와 reprocess_of 연결 생성, 기존 스냅샷 불변 |
| 명시적 빈 Cloud 입력 | 0건·complete |
| REST-v2 형태 입력 | 1건 수집, 불완전 증거는 partial 유지 |

기존 Go 테스트 파일은 발견되지 않았고 테스트 코드는 추가하지 않았다.
저장·백업 통합의 더 넓은 이전 증거는
[Jira 검증 기록](../validation/PHASE_06_JIRA_INGESTION.md)에 있다.
오늘 백업·복원, 손상·강제 종료, 실제 Jira 요청, 인증·필드 발견,
새 Gmail 수집, AI 실행, 전체 프로젝트 검증은 수행하지 않았다.

## 연결에 필요한 다음 입력

[Jira 연결 준비서](../setup/JIRA_CONNECTION_PREPARATION.md)에 입력표,
배포·인증별 확인사항, 구현 경계와 완료 증거를 정리했다.
후속 답변에서 사용자는 Cloud API 직접 연동, `cjenm.atlassian.net`,
`SWMPFE` 프로젝트와 `1704` 보드를 지정했다. 본인 할당 업무 및 To Do·2주 이내
처리 조건으로 보고서를 만들고, 이후 다음 업무를 코드 작업으로 연결하려는 목적이다.
할당 조건과 To Do/날짜 조건의 AND/OR 관계는 확인 중이며 실행 범위로 확정하지 않았다.
인증 세부사항, 본인 식별, 보드 필터·상태·날짜 필드도 실제 조회 전이다.
실제 사용자 ID·custom field ID는 승인된 메타데이터 조회로 확인할 수 있으므로
사용자가 미리 모두 알아야 하는 것은 아니다. 비밀값은 문서에 기록하지 않는다.

이번 문서는 실제 접속이나 새 외부 계약을 승인하지 않는다.
Cloud에 맞는 읽기 범위가 정해지면 P6-02b의 구체적인 변경 범위·검증안을 제시하고,
확정된 방향 안에서 구현한다. Jira 보고서 의미와 AI 전달은 별도 후속 단계다.
