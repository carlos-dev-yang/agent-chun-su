# CHAT-UX-05 — 채팅 서비스 언어 설정 준비안

상태: 설계 제안. 언어 설정·다국어 출력·Telegram 메뉴 등록은 아직 구현하지 않았다.
사용자는 지연 안내를 제외하고 오류·중단 안내를 명확히 하며, JSON 상태를 선택한
언어로 자연스럽게 제공할 방법을 요청했다. 지연 안내 제외는 확정된 방향이고,
아래 설정 범위와 한국어·영어 지원은 권장안이다.

## 1. 권장 설정 방식

서비스 언어와 말투를 별도 설정으로 둔다. 언어는 한국어·영어처럼 **어느 언어로
표현할지**, 말투는 정중함·친근함·간결함처럼 **어떻게 표현할지**를 결정한다.
현재 말투는 한 데이터 홈의 Telegram·로컬 자연어 채팅에 공통 적용된다.
언어도 같은 범위에 하나만 저장하는 구성이 현재 단일 소유자 구조에 맞는다.

| 항목 | 권장안 |
|---|---|
| 기본 언어 | 한국어 — 설정이 없는 기존 사용자의 동작 유지 |
| 최초 지원 언어 | 한국어 `ko`, English `en`; 지원 목록은 구현 전에 확정 |
| 변경 | AI가 없어도 동작하는 `/언어`, `/language` |
| 적용 대상 | 자연어 채팅 답변, 상태·오류·중단 안내, 도움말·설정 메뉴 등 채팅 시스템 문구 |
| 적용 시점 | 저장 성공 후 새 명령 출력·새 답변 생성부터; 생성 중인 답변을 취소하지 않음 |
| 유지 | 재시작·새 대화 후에도 유지; 언어 초기화는 기본 한국어로 복귀 |
| 설정 범위 | 한 데이터 홈을 사용하는 소유자의 Telegram·로컬 자연어 채팅 공통 |

사용자가 영어 문장이나 코드를 보냈다는 이유로 저장 언어를 바꾸지 않는다.
Telegram은 선택적인 사용자 언어 필드를 제공하지만, 이 값은 봇 내부의 명시적
언어 선택과 별개다. 첫 구현에서는 자동 선택을 넣지 않는 편이 단순하다.
향후 초기 제안에 활용하더라도 사용자가 고른 값을 덮어쓰지 않는다.
[Telegram User](https://core.telegram.org/bots/api#user).

작업 보고서·평가자·별도 업무 실행기에는 기존 지침을 유지한다. 번역을 요청한
본문·인용문·코드·명령어·작업 ID 등은 원래 의미와 형식을 보존한다. 별도 호스트나
다른 소유자 사이의 언어 동기화는 이번 제안에 포함하지 않는다.

## 2. 사용자가 보는 설정 흐름

`/언어`와 `/language`는 현재 언어에 관계없이 사용할 수 있게 한다.

```text
/language

언어를 선택해 주세요. / Choose a language.
1. 한국어
2. English
현재: 한국어
```

번호 또는 `ko`, `en`으로 선택하고, 저장에 성공하면 새 언어로 바로 확인한다.
예: “Language set to English. Future chat replies and system notices will use English.”

직접 명령도 제공한다: `/language en`, `/language current`, `/language reset`,
`/language cancel`. 한국어 별칭은 `/언어 현재`, `/언어 초기화`, `/언어 취소`다.
미지원 언어는 임의 저장하지 않고 지원 목록을 보여준다. 선택 중인 메뉴 상태는
메모리에만 두고, `/cancel`·`/reset` 같은 기존 제어 명령은 원래 처리 경로로 넘긴다.
언어 메뉴와 말투 메뉴를 동시에 선택 대기 상태로 남겨 숫자 입력이 잘못 저장되는
일이 없도록, 한 채팅의 설정 대화는 한 번에 하나만 활성화한다.

Telegram 기본 명령 이름은 `/status`, `/cancel`, `/language`처럼 고정하고
설명만 현지화한다. 실제 메뉴 동기화는 기존 개인 대화 범위와 언어별 목록을 확인한
뒤 적용하는 별도 작업이다. 앱 내 언어를 바꿨다고 Telegram 자체 UI 언어가 바뀌지는
않는다. Telegram 메뉴의 언어별 선택 규칙과 앱 설정의 차이는 메뉴 적용 시 확인한다.
[setMyCommands](https://core.telegram.org/bots/api#setmycommands).

## 3. 저장과 표시 책임

언어는 자유로운 지침 문장이 아닌 제한된 설정 값이다. 기존
`instructions/chat-tone.md`와 분리해 private `preferences/chat.json`에 다음처럼
저장하는 방식을 제안한다. 정확한 경로·필드는 구현 시 확정할 내부 형식이다.

```json
{"version": 1, "language": "ko"}
```

AI 실행기·권한 설정을 가진 `config.json` 전체를 채팅 언어 명령으로 다시 쓰지 않는다.
DB 마이그레이션도 필요하지 않다. 파일은 크기 제한·허용 값 검사·원자적 교체를
적용하고, 언어 이외의 설정을 바꾸지 않는다. 여러 설정 값이 추가되면 파일 소유와
동시 쓰기 규칙을 먼저 정한다. 최초 버전은 언어 한 항목만 저장한다.

파일 없음은 한국어 기본값이다. 저장 실패 시 성공했다고 답하지 않는다. 읽기 실패나
손상 시 한국어 대체 출력과 짧은 한·영 복구 안내로 `/language reset`에 접근할 수 있게
한다. 설정 파일 오류가 수신기·관리 명령 전체를 중단시키지 않도록 한다. 원문이나
파일 경로를 오류 메시지에 포함할 필요는 없다.

| 계층 | 책임 |
|---|---|
| 호스트·운영 감시기 | 연결·작업·오류·신선도 등 사실과 식별자를 제공 |
| 언어 설정 | 허용된 언어 읽기·저장·기본값 처리 |
| 공통 표시부 | 상태 및 오류 코드와 값을 언어별 검토된 문장으로 변환 |
| 채팅 AI | 선택한 언어와 말투를 매 생성 직전에 전달받아 일반 답변 작성 |
| Telegram·로컬 채팅 | 같은 표시부를 사용하고 각 채널의 전달·중단 결과 처리 |

JSON은 내부 상태 교환과 기존 CLI `--json` 진단 경로에 유지한다. 채팅 `/status`는
구조화된 사실에서 문장을 직접 만든다. AI 번역을 거치지 않아 AI가 실패한 상황에도
상태·오류 안내를 제공할 수 있다. 예를 들어 관측이 해당 사실을 뒷받침할 때:

> 현재 요청을 받을 수 있어요. Telegram 연결은 정상이고, 처리 중인 답변은 없습니다.

> I can accept requests now. Telegram is connected, and no reply is being generated.

확인 불가·오래된 관측·복구 필요는 각기 다른 문구로 표시한다. 프로세스 생존만으로
다음 모델 응답의 성공을 보장하지 않는다. `/status`에 감시기 정보를 추가할 때는
[창구 점검](CHAT_ENTRYPOINT_AUDIT_2026-09-13.md)의 순환 의존성 경계를 유지한다.

오류 기록의 안정적인 `Code`·ID·횟수·시각은 유지하고, 표시 단계에서 요약과 다음
행동을 현지화한다. 기존 오류 파일을 번역하거나 다시 쓸 필요는 없다. 새로운 지원
언어는 핵심 시스템 문구가 모두 준비됐을 때만 선택 목록에 노출한다.

AI에는 기본 기능·출력 계약, 서비스 언어, 말투의 관계를 명시한다. 커스텀 말투 안에
다른 언어 지시가 있어도 서비스 언어를 우선하며, 보고서 번역 등 사용자가 요구한
산출물 언어는 별도로 존중한다. 현재 기본 Skill의 사용자 언어 지침과도 맞춰야 한다.

## 4. 오류·중단 안내와 구현 순서

지연 안내·반복 진행 메시지·typing 타이머는 추가하지 않는다. 사용자가 보낸 명령이나
실제 종료 결과에 따라 필요한 안내를 제공한다. 시간 초과, 처리 실패, 실행 결과
불확실, 중단 요청, 중단 정리 완료, 복구 실패를 구분한다. 원 작업의 자동 재실행이나
불확실한 답장의 자동 재전송은 추가하지 않는다.

1. **CHAT-UX-03:** 현재 언어로 오류·중단 결과를 먼저 명확히 한다.
2. **CHAT-UX-05:** 저장 범위·최초 지원 언어 결정 후 언어 명령과 공통 문구 목록을 구현한다.
3. **CHAT-UX-02:** `/status`를 같은 언어 설정을 사용하는 문장으로 제공한다.
4. **CHAT-UX-04:** 지원 언어의 메뉴 설명과 Telegram 실제 등록을 별도로 검증한다.

완료 확인에는 언어 선택·초기화·재시작 유지, AI 없는 설정·상태·오류 안내, 말투와
언어 우선순위, 설정 저장 실패, 관측 없음·오래됨 표시, 채널 간 일치가 필요하다.
현재 문서는 소스 조사와 Sol 설계 검토에 근거한 제안이며, 다국어 동작 검증의 증거가 아니다.
