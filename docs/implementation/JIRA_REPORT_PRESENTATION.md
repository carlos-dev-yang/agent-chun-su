# Jira 보고서 표시 기준

2026-09-07 사용자 피드백을 반영한 Markdown 표시 기준이다.
수동 보고서에 적용했으며, 자동 생성 가이드 구현 시 같은 기준을 사용한다.
조회 조건·런타임 계약을 변경하는 문서는 아니다.

## 구성

1. 맨 앞 YAML 코드 블록: 기준일, 기한 조회 기간, 추가 대상, 수집 시각·시간대.
2. 조회 정보 표: 보드 링크, 스프린트 또는 칸반, 담당자, 수집자, 수집 원문 링크.
3. 업무 현황: 중복 없는 보고 건수와 세 그룹의 건수를 짧은 불릿으로 표시.
   To Do 합계를 추가하면 전체 보고 건수의 부분집합임을 밝힌다.
4. 하이라이트·남은 업무: 오늘, 이번 주, 기한 경과, 기한 미등록 일정,
   다음 착수일 순으로 간결하게 정리한다. 별도의 수행 제안 설명은 반복하지 않는다.
5. 상세 표: 14일 내 기한, 기한 경과, 기한 없는 To Do.
6. 마지막 코드 작업 후보 표: 업무와 착수에 필요한 입력만 표시한다.

## 표와 문장

- 업무와 다음 확인할 일을 중심으로 쓰고, 다음 확인할 일에 가장 많은 공간을 배정한다.
  Markdown에서는 짧은 식별자·상태·날짜와 줄바꿈으로 보조 열을 줄인다.
  고정 너비를 지원하는 렌더러에서는 다음 확인할 일, 업무 순으로 너비를 배정한다.
- 시작일과 기한은 한 열 안에서 `<br>`로 두 줄 표시한다.
  기준 연도와 같으면 월/일, 다르면 연도까지 표시한다.
- 기한 경과 표에는 별도의 경과 일수 열을 둔다. 기준일과 기한의 달력 날짜 차이를 쓴다.
- 기한 없는 To Do 표는 업무·시작·다음 확인할 일만 남긴다.
- 업무 제목은 의미를 보존해 줄이고 Jira 링크로 연결한다. 전체 제목과 설명은 원문에 보존한다.
- 반복 상태 설명, 과도한 제안 문구, 일반적인 조회 한계 설명은 본문에서 제거한다.
  실제 누락·수집 실패 등 결과 해석에 영향을 주는 문제는 숨기지 않는다.

## 집계와 보존

- 상세 그룹 간 이슈는 중복 없이 한 번씩 표시한다. 하이라이트·후보의 재언급은 합산하지 않는다.
- 이번 주는 기준 시간대의 월요일~일요일이며 오늘을 포함하면 표시한다.
- 제목·설명의 행사일은 등록된 시작일·기한으로 바꾸지 않는다.
- 같은 수집 자료의 편집이면 기존 수집 시각을 유지한다.
- 표시를 줄여도 수집 원문·근거·기존 보고서는 비공개 저장소에 보존한다.
- 코드 작업 후보는 실제 착수나 완료 가능성에 대한 확약이 아니다.
