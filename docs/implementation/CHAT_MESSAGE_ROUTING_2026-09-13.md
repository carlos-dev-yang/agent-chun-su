# CHAT-TRACE-01 — 메시지 분류와 호스트 결과 보존

2026-09-13 사용자는 중간 호스트 결과를 추적 관리용으로 저장하고, 채팅 처리
과정에서 전송할 메시지와 내부 기록을 분류하도록 요청했다. 기존 Go 접수 처리부와
private 파일 저장을 확장하며, DB 변경이나 새 관리 화면은 포함하지 않는다.

## 적용 방향

- 작업을 동반한 AI의 사전 안내는 내부 진행 기록으로 분류하고 채팅에 보내지 않는다.
- 호스트 처리 결과는 실제 결과와 요청·세션·단계 식별자를 함께 보존하고 AI의
  후속 답변에 사용한다. `[호스트 처리 결과] action: status` 메시지는 보내지 않는다.
- 작업 없는 AI 답변은 최종 답변 또는 추가 질문으로 사용자에게 전달한다.
- 분류 기준은 호스트 코드가 소유한다. 알려지지 않은 이벤트는 기본적으로 숨긴다.
- 오류와 필요한 조치는 기존 안전한 오류 안내로 전달한다. 고정 관리 명령과
  로컬 인증 입력·보고서 표시 콜백은 기존 사용자 상호작용을 유지한다.
- Telegram 접수는 기존 👀 반응을 유지한다. 중간 결과를 숨겨도 후속 AI 답변을
  위한 메모리 이력은 보존한다.

## 저장 경계

`chat/<session>/<generation-step>/action.json`의 기존 실행 의도·상태·해시
기록을 확장하여 허용된 호스트 결과를 저장한다. 별도 `message.json`에는
메시지 종류·전송 분류·본문 해시와 전송 시도 결과를 기록한다. 같은 사용자 요청의
여러 AI 단계를 하나의 요청 식별자로 연결하고 Telegram update 식별자도 연결한다.

사용자와 AI의 대화 본문, 인증 입력, 보고서 본문, 원시 예외·제공자 진단은 저장하지
않는다. 호스트 결과는 작업별 허용 필드만 보존하며 기존 artifact 크기 한도와 private
파일 접근 규칙을 사용한다. 인증·보고서 표시 결과는 본문 없이 상태만 보존한다.
보존 실패 시 실행·전송을 중단하고, 실행 후 실패는 불확실 상태로 보고한다.
중간 기록이나 전송 기록은 작업 재실행을 허가하지 않는다.

## 완료 증거

상태: 구현·로컬 실행 검증 완료. 관련 패키지 컴파일·정적 검사와 실제 Codex 상태 조회
대화에서 최종 답변만 표시되는 것을 확인했다. 결과 내용, 요청별 단계 연결,
내부/suppressed 및 사용자/sent 기록과 private 파일 권한도 확인했다.
일반 답변 경로도 검증했으며 새 테스트 코드는 만들지 않았다.
[검증 기록](../validation/CHAT_MESSAGE_ROUTING_2026-09-13.md)은 실제 실행한 검사와
미수행 시나리오, 수신기 적용 결과를 구분한다. 실제 Telegram 메시지 표시는 사용자의
다음 DM으로 확인하며, 별도의 관리 화면이나 자동 재실행은 이 작업에 포함하지 않는다.
