# CHAT-UX-05/02 — AI 답변 언어와 영어 시스템 안내

상태: 선택 범위 구현·검증·로컬 운영 반영 완료(2026-09-14 KST).
2026-09-13 사용자가 이 작업을 goal로
등록하고 언어를 선택할 수 있게 구현하도록 요청했다. 시스템 안내까지 모든 언어의
번역을 관리할 필요는 없으며 영어 안내를 사용할 수 있다는 방향을 선택했다.
이 문서는 이전 [언어 설정 준비안](CHAT_LANGUAGE_PREPARATION_2026-09-13.md)의
한국어·영어 번역 목록 제안을 대체한다.

## 목표와 범위

AI 답변의 언어는 사용자 설정을 따르고, 핵심 시스템 안내는 영어로 제공한다.
상태·오류·중단 안내를 위해 AI를 추가 호출하거나 언어별 시스템 번역 목록을
유지하지 않는다. 기존 접수 반응과 오류·중단 구분을 유지하며 지연 안내는 추가하지 않는다.

| 항목 | 구현 방향 |
|---|---|
| 기본값 | `auto`: 기존 대화 Skill처럼 사용자 메시지의 언어를 따름 |
| 언어 선택 | `/language TAG`, `/언어 TAG`; 예: `ko`, `en`, `ja`, `zh-Hant`, `pt-BR` |
| 선택 범위 | 검증·정규화한 언어 태그; 시스템 번역 유무로 AI 답변 언어를 제한하지 않음 |
| 조회·복귀 | `/language`, `/language current`, `/language auto`, `/language reset` |
| 입력 방식 | 상태 없는 명령; 번호나 다음 일반 메시지를 언어 선택으로 소비하지 않음 |
| 저장 범위 | 데이터 홈 하나의 Telegram과 로컬 자연어 채팅 공통 |
| 저장 위치 | private `preferences/chat.json`; 실행기·권한 config와 말투 Markdown에서 분리 |
| 적용 시점 | 새 AI 생성 단계 직전에 읽음; 진행 중인 생성의 지침은 유지 |
| 시스템 안내 | 핵심 명령·설정·상태·오류·중단 문구는 영어 |

문법상 유효한 언어 태그를 저장할 수 있다는 것은 모든 언어에서 모델의 응답 품질을
검증했다는 뜻이 아니다. 자동 모드는 메시지마다 영구 설정을 다시 쓰지 않는다.
명시적으로 고른 언어는 앱·플랫폼 언어 또는 입력 문장을 이유로 덮어쓰지 않는다.

## 언어·말투·작업 권한

호스트가 현재 언어와 말투를 매 생성 직전에 구조화해 전달한다. 선택 언어는 일반
답변의 언어를 정하고, 말투는 그 언어 안에서 표현 방식을 정한다. 커스텀 말투 안의
다른 언어 지시가 명시적인 언어 설정을 바꾸지 않는다. 번역문·산출물에 대해 사용자가
요청한 언어, 인용문·코드·식별자는 해당 요청과 원문을 존중한다.

기본 기능·출력 형식·권한 지침은 그대로 유지한다. 언어 설정은 별도 작업 실행기,
보고서 생성·평가자의 지침이나 외부 서비스 권한을 바꾸지 않는다. `/reset`과 재시작은
저장된 언어와 말투를 지우지 않는다. 언어 초기화는 `auto`로 복귀한다.

## 실패와 상태 표시

언어 설정은 AI가 없거나 복구가 필요한 상황에도 사용할 수 있다. 잘못된 언어 태그는
저장하지 않고 올바른 예를 보여준다. 저장 성공을 확인한 뒤에만 변경 완료를 알린다.
없는 파일은 기본값이고, 손상·읽기 실패는 안전한 영어 복구 안내와 기존 오류 기록으로
드러낸다. `/language reset`으로 설정을 복구할 수 있다. 데이터베이스 마이그레이션이나
기존 실행기 설정 파일 전체의 재저장은 필요하지 않다.

채팅 `/status`는 현재 호스트의 구조화된 관측값을 읽기 쉬운 영어 문장으로 표시한다.
컨트롤러 이용 가능 여부, 수신기 관측 유무·신선도, 수신 상태, 활성 AI 요청·복구 차단,
업무 실행기·큐·작업 상태를 구분한다. 읽을 수 없는 관측을 정상 또는 중지로 확정하지 않는다.
내부 호스트 결과, 추적 기록과 기존 CLI JSON 진단 경로는 구조를 유지한다.
이번 범위에 새로운 감시기 연동 API나 감시 판정 복제는 추가하지 않는다.

영어 시스템 안내는 필요한 다음 명령과 사실을 제공한다. 기존 매뉴얼·보고서 본문,
사용자 작성 말투, 인증 설정 전체의 번역은 이 목표가 아니다. Telegram의 봇 명령 메뉴
등록과 다른 알림 채널 연결은 별도 작업이다.
