# 실행 게이트 점검 규약

상태: 2026-09-07 사용자가 요청한 메일·Jira 실행/평가 반복 점검 절차.
이 문서는 실행기 바깥의 호스트 점검 규약이다. 실행기에게 관리자 명령이나
수집 권한을 부여하는 문서가 아니며, 활성 버전 선택을 대신하지 않는다.

## 점검 단위

수집 결과, 실행 결과, 결과 평가를 별도로 판정한다. 수동으로 만든 보고서나
모델의 성공 선언을 프레임워크 실행 성공으로 세지 않는다. 입력이 합성이면
실제 모델을 호출했더라도 합성 입력 검증이라고 기록한다.

한 회차에는 다음 근거를 남긴다.

1. 계정/프로젝트/보드/조회 기간/내용 범위와 수집 완료·누락 여부.
2. 변경 불가능하게 보존된 입력, 원문 해시와 수집 기록.
3. job/attempt, 실행기 버전·모델, 지침·스키마·입력·제한의 고정 버전.
4. 실제 제공된 도구와 실제 호출 기록. 허용된 원문 읽기와 범위 밖 요청의 거부.
5. 원문 조회 증거, 결과 스키마, 출처 연결과 대상 누락에 대한 호스트 판정.
6. 별도 결과 평가, 개선 가설, 비활성 후보 버전, 동일 입력의 비교 실행.

## 통과와 미확인

- 수집 성공은 실제 허용 범위의 데이터를 보존하고 페이지 종료 또는 누락을
  정확하게 기록한 경우다. 웹 화면이 열린 사실만으로 자동 수집 성공이라 하지 않는다.
- 실행 성공은 원문 도구가 실제 호출되고 호스트가 입력/권한/출력 계약을
  확인한 경우다. 도구가 없는데 만들어진 빈 JSON은 성공이 아니다.
- 출력이 형식상 맞아도 허용하지 않은 도구 사용이 관찰되면 게이트 실패로
  기록한다. 이벤트 관찰만으로 모든 숨은 동작의 부재를 증명했다고 하지 않는다.
- `partial`, 필요한 사용자 질문, 원문 접근 불가는 각각 보존한다. 이를
  완전 수집·정상 완료로 바꿔 성공률을 높이지 않는다.
- 메일 읽음 상태 변경, 메일/일정 변경, Jira 변경, 외부 메시지 전송은 수집
  검증에 포함하지 않는다. 읽기 권한을 확대해야 하면 그 결정은 사용자에게 남긴다.
- 스킬·룰·스키마의 원본과 평가 기대값은 실행기 바깥에 저장한다. 실행기에는
  해당 attempt에 필요한 지침 사본과 공개 출력 계약만 전달한다.

## 개선 반복과 중단

현재 사용자의 명시적 지시에 따라 같은 원인의 실패가 3회 확인되면 해당
접근을 중단한다. 이 기준은 이번 개선 루프에 적용하며, 기존 작업의 전체
시도 횟수 상한을 자동으로 변경하지 않는다.

회차별로 원인 식별자, 관찰, 변경한 가설/설정, 결과, 같은 원인 누적 횟수를
남긴다. job이나 후보 ID를 바꿔도 같은 원인의 횟수는 초기화하지 않는다.
원인을 조사한 읽기 작업과 정상적으로 거부된 부정 검증은 실패 재시도로
세지 않는다. 실패 원인이 해결되었다는 새로운 실행 근거가 있으면 해결을
기록하고 다음 문제로 넘어간다. 살아 있는 실행의 관찰 시간이 만료됐다는
이유만으로 새 실행을 만들지 않는다.

후보는 비교 근거와 함께 보존한다. 운영 중인 활성 룰 채택, 계정 권한 확대,
백그라운드 일정 활성화는 단순한 테스트 통과로 추론하지 않는다.
