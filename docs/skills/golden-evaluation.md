# 골든셋 평가 규약

상태: 2026-09-07 반복 검증의 평가 절차. 개인별 중요도와 유용성은 사용자가
검토하지 않았다. 합성 사례의 사실 기대값과 개인의 선호를 구분한다.
이 문서와 사례별 기대값은 실행기 패키지에 포함하지 않는다.

## 기대값 작성

입력과 기준 시각을 먼저 고정하고, 결과를 보기 전에 가능한 범위에서
기대값을 작성한다. 각 기대값은 원문 ID와 연결하여 필수 사실, 금지 오류,
허용 대안으로 표현한다. 모델 문장과 정확히 같은 표현을 요구하지 않는다.

수동 검증에서도 실행 전에 기대값의 정확한 바이트를 별도 파일로 보존하고
해시를 실행 시작 기록에 고정한다. 평가자는 완료를 알린 파일을 덮어쓰지
않는다. 메타데이터 보강도 새 버전으로 저장하며, 호스트는 해시가 고정된
사본을 사용한다. 이미 갱신된 파일의 과거 버전은 기록된 해시와 정확히
일치할 때만 복원본으로 채택한다. 복원할 수 없으면 사전 고정 증거가 없다는
한계를 남기고 결과를 본 뒤 작성한 기준과 구분한다.

- 메일: 직접 요청과 단순 알림 구분, 업무 병합/분리, 현재 일정, 광고 제외,
  운영상 조치 보존, 완료 여부 미확인, 누락 고지, 원문 지시 무시를 점검한다.
- Jira: 본인/프로젝트/보드 범위, 미완료 업무, 오늘~14일 뒤 양끝 포함,
  기한 경과, 기한 없는 지정 TODO, 그룹 간 중복 없음과 대상 전수 반영을
  점검한다. 설명에 나온 행사일을 등록 기한으로 바꾸거나 날짜 경과를
  실제 납기 지연·완료 가능 공수로 단정하지 않는다.
- 수집 평가와 요약의 의미 평가는 구분한다. 수집하지 못한 내용을 요약에서
  놓쳤다는 이유로 모델 분류 오류를 단정하지 않는다.
- 원문 필드의 존재 여부와 값을 따로 확인한다. 현재 Jira v1에서는 필드
  자체가 없으면 `not_returned`, 명시적 `null`이나 빈 문자열이면 `empty`다.
  기대값에서도 이를 구분하며, API가 반환한 빈 값으로 사용자의 작성 여부나
  API 밖의 접근 가능성을 추측하지 않는다.

사례/루브릭의 `draft`, `validation`, `human_reviewed` 표기를 유지한다.
AI가 만든 기대값이나 평가를 사람의 검토로 기록하지 않는다. 사실상 자동
대조 가능한 항목이 통과해도 개인 유용성까지 승인됐다고 하지 않는다.

## 독립 판정

평가에는 입력·attempt·결과 artifact·사례·루브릭 버전과 평가자/역할을
연결한다. 모든 기준에 `pass`, `fail`, `unknown` 중 하나를 기록하고
원문 근거와 이유를 남긴다. 검토 시간이나 비용은 측정한 경우만 기록한다.

이번 루프의 전체 판정 규칙은 다음과 같다.

| 기준별 판정 | 전체 판정 |
|---|---|
| 모든 기준 통과 | `pass` |
| 실패가 있고 미확인은 없음 | `fail` |
| 일부 기준 미확인과 통과/실패가 함께 있음 | `mixed` |
| 사용 가능한 결과가 없거나 의미 평가를 할 수 없음 | `unevaluable` |

불완전한 본문 접근 때문에 의미 평가를 할 수 없으면, 접근 한계를 정직하게
고지했는지와 같은 관찰 가능한 항목만 개별 판정하고 전체는 `unevaluable`로
남긴다. 실패 기준이 있는데 전체를 `pass`로 기록하지 않는다.

기존 평가를 덮어쓰지 않는다. 재평가에는 새 기록을 만들고, 비교에는 실제
사용한 평가 ID와 이전 평가와의 불일치 여부를 명시한다. 비교 가능성은
품질 통과와 다르며, 비교가 가능하다는 사실만으로 개선을 주장하지 않는다.

## 후보 비교와 완료 근거

문제를 발견한 입력으로 후보를 개선하고, 별도 확인 입력에서도 회귀를
점검한다. 독립 확인 사례가 없으면 그 한계를 남긴다. 실패 실행과 미평가
결과도 비교 분모에 포함한다. 지침, 실행기, 도구, 예산, 평가 규칙 중 달라진
조건을 표시하며, 평가 규칙 변경 시 양쪽 결과를 같은 기준으로 재평가한다.

임의의 점수/합격률로 완료를 선언하지 않는다. 사용자 요청의 각 항목에 대해
실제 수집, 실행 게이트, 출처 근거, 독립 평가, 후보 재실행, 회귀 확인 증거가
있는지 대조한다. 사람의 선호·채택 결정이 남으면 기술 검증 완료와 구분한다.
